# 拾光記帳 Daybook V1.9.8｜固定收支有效期間／更換方案

本版本是從使用者提供的 **拾光記帳 1.9.7.zip** 修改並整合的**完整 GitHub Pages 版**，不是單獨的日期模組。全部檔案請在 GitHub Pages 發布資料夾的根目錄直接覆蓋。

## 此次新增

1. 固定收支編輯視窗新增「有效終止日期」：可以留白持續有效，或指定最後可產生待入帳期別的日子（包含當日）。
2. 「填入 12 期終止日」「填入 24 期終止日」「持續有效」快捷操作：期數依首次扣款日期與週期間隔推算。此處代表**扣款期數**，不一定等同合約法定期間，仍請核對業者合約。
3. 每張固定收支模板新增「更換方案」按鈕：填舊方案終止日、新方案首次扣款日、新項目名稱及金額，一次保存兩個獨立模板；拒絕日期重疊。
4. 已終止的模板保留在下方設定清單並顯示「已終止」，不再產生「待確認期別」；已入帳的交易不會被刪除或改價。
5. 同名、不同門號/不同方案以各自模板 ID 獨立處理，避免 899 / 799 元混用。
6. 起始日、終止日與新舊方案關聯欄位隨本機 IndexedDB、JSON 備份和既有 `planner` 雲端同步資料通道保存；**未修改 Apps Script Code.gs**。
7. 版本常數、version.json、check-update.html、PWA 快取與 JS/CSS 版本化檔名全部更新至 1.9.8。

## 重要使用例

- 舊月費 899 元，每月 11 日扣款，最後有效扣款是 2026-10-11：將舊方案終止日設為 `2026-10-11`。
- 新月費例如 699 元從 2026-11-11 開始：對舊方案按「更換方案」，輸入新日期及金額。下期只會出現新方案；已確認入帳的舊 899 元交易照舊。
- 截圖裡的 899 與 799 元若是兩個門號，**請分別編輯各自的模板**。不要把兩筆合併成同一筆。
- **結束日期並不自動修改已經入帳的收支明細**；固定收支模板僅負責產生「待確認」的候選項目。
- 舊版本原本沒有終止日的模板，升級後會預設「持續」，請按你的實際合約逐項補上終止日；不會替你猜測終止時間。

## 安裝與資料保護

1. 在目前 V1.9.7「資料備份與設定」先下載完整 JSON，確認 JSON 包含 `records` 及 `planner`（含 recurring 模板）。
2. 解壓縮後把本包的 `index.html`、`app.v1.9.8.js`、`styles.v1.9.8.css`、`sw.js`、`version.json`、`check-update.html`、`manifest.webmanifest` 和 icons 資料夾放在 GitHub Pages 發布目錄**同一層**；不要多包一層資料夾。
3. GitHub Pages 部署完成後，開 `你的網站網址/check-update.html` 應顯示 V1.9.8，再開主網站確認左上版本 V1.9.8。
4. 不要執行「清除網站資料」或刪除 IndexedDB；本版沿用 `daybook_local_v1`，目前原始交易資料不須重匯入。
5. Google Apps Script 及金鑰不必更改。連線後先以一筆**尚未入帳的模板**測試設定終止日、跨裝置讀回；避免用真實帳目試按「確認入帳」。

## 測試狀態

- `node --check` JavaScript 語法通過。
- 14 項與新版整合後程式相關的日期/換方案測試通過；另有先前獨立核心模組的 14 項測試通過。
- Playwright/Chromium 以靜態版面檢查 320、375、430、768、1366px：新增模板與更換方案視窗不超出螢幕。
- 目前執行環境禁止瀏覽器導航到本機正式測試站，**未完成整套網站的 IndexedDB 互動驗收**；也**未連到使用者的正式 Google Sheets 做跨裝置端到端測試**，上線後務必實測。

**本包不含任何私人帳目、同步金鑰或 Google 試算表私密 ID。**
